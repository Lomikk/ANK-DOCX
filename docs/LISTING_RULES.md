# Программные листинги в QMD и DOCX

## Нормативные источники и их приоритет

1. [СТО ЮУрГУ 04–2008](https://www.susu.ru/sites/default/files/book/standart_kursovoe_i_diplomnoe_proektirovanie_04-2008_yuurgu_1.pdf), п. 4.2: Times New Roman 14 пт относится к основному тексту пояснительной записки; заголовки не выделяются другим цветом. П. 4.3 регулирует рамку **листа**, а не блока программного кода.
2. П. 4.14 допускает программы в приложениях, а п. 4.15 отдельно рассматривает сложенные «гармошкой» распечатки листингов. П. 4.27 отсылает к ЕСПД для самостоятельных программных документов. Конкретного шрифта кода, рамки блока и цветовой схемы в этих пунктах нет.
3. [ГОСТ 19.401–78](https://protect.gost.ru/gost/details/e71e0951-ee1a-441f-b0c0-be3f3681c2f0) регулирует отдельный документ «Текст программы», ссылается на ГОСТ 19.105–78 и не предписывает Courier New или выделение цветом. [ГОСТ 19.106–78](https://protect.gost.ru/gost/details/237d9e0c-a8a8-40a2-a2f5-f8182da346a8) прямо **не применяется** к документу «Текст программы».
4. Отсутствующие параметры принимаем как **стиль ANK** по образцу [методических указаний Тюменского индустриального университета, п. 5.14](https://www.tyuiu.ru/sveden/files/rif/MU_DP_09.02.01_KSt_2023_2.10.pdf): Courier New 12 пт, одинарный интервал, логические отступы, комментарии, номер и название листинга сверху. Это не обязательные правила ЮУрГУ, а вторичный источник проектного решения.

## Выбранный MVP

| Элемент | Решение | Статус |
|---|---|---|
| Исходный код | Обычные, редактируемые в Word блоки Pandoc/Quarto | Штатный механизм |
| Шрифт | Courier New 12 пт, одинарный интервал | Стиль ANK из рекомендаций ТИУ |
| Отступы и пустые строки | Сохраняются из исходника; фрагмент не исполняется без явного желания автора | Стандартный fenced code |
| Подсветка | Цветные Word-стили токенов, курсив для ключевых слов и комментариев, альтернатива `monochrome` с отдельным reference-docx | Курсив — рекомендация ТИУ, цвет не является требованием СТО |
| Фон и рамка | Без дополнительного фона и прямоугольника вокруг кода | Стиль ANK, не путать с рамкой листа |
| Подписи и ссылки | `lst-cap`, `#lst-id`, `@lst-id` без ручных номеров | Стандартные механизмы Quarto |
| Слова на русском | `Листинг` для подписи и `листинг` для ссылки | `crossref` расширения |
| Полные программы | Преимущественно приложение; короткие фрагменты допустимы в главе | Разделение сценариев, не запрет СТО |
| Нумерация в приложении | Желательна форма `Листинг А.1` | Quarto Book формирует `Листинг A.1` с латинской буквой; это статическая нумерация Quarto, не поле `SEQ` Word |
| Подпись над кодом слева, без абзацного отступа | По рекомендациям ТИУ | Quarto центрирует подпись и код в технической таблице; финализатор убирает таблицу и выравнивает оба абзаца слева, не затрагивая рисунки |

Не следует переносить все требования ТИУ как нормативные проверки ЮУрГУ. Особенно это относится к обязательному размещению *всех* листингов в приложениях: СТО 04 допускает этот вариант, но не запрещает краткие фрагменты в основном тексте.

### Монохромный вариант

Quarto/Pandoc записывает цвет подсветки в стилях Word, поэтому смена `syntax-highlighting` **сама по себе не удаляет** цвета из готового DOCX. Для монохромной печати укажите в метаданных рабочего Book:

```yaml
format:
  academic-docx:
    syntax-highlighting: monochrome
    reference-doc: _extensions/academic/academic-monochrome.docx
```

Обе версии reference-docx различаются только цветами токенов кода и сохраняют прочие академические стили. Достаточно использовать один из вариантов на весь документ.

## Авторский синтаксис

См. [`academic/examples/listings.qmd`](../academic/examples/listings.qmd). Короткий пример:

````markdown
См. @lst-speed.

```{#lst-speed .python lst-cap="Вычисление скорости"}
def speed(distance, time):
    return distance / time
```
````

Класс `.python` создаёт **неисполняемый** блок; `{python}` запускает вычисляемую ячейку, для которой Quarto предлагает отдельные `lst-label` и `lst-cap`. Не вводим новый обязательный синтаксис вместо встроенного. Полные правила: [Quarto Cross References](https://quarto.org/docs/authoring/cross-references.html#code-listings), [Quarto Word Syntax Highlighting](https://quarto.org/docs/output-formats/ms-word.html#syntax-highlighting).

## Граница текущей проверки

- Изменение `academic.docx` задаёт формат **кода**, а не самостоятельно формирует подписи или номера. Crossref принадлежит Quarto, а не Word-адаптеру.
- В Windows-сборке Quarto 1.10.19 подтверждены подписи «Листинг 2.1», «Листинг 2.2», разрешение ссылок `@lst-*` как гиперссылок на закладки, сохраняемый текст кода и стили токенов. Quarto изначально заворачивает подписанный листинг в таблицу 1×1; финализатор распаковывает её и выравнивает подпись и код слева. После финализации ещё проверить визуальное размещение, перенос длинных строк и `monochrome` в полноценном Quarto Book.
- Ссылки на листинги — нативные Word-гиперссылки на закладки, однако номера формируются Quarto как текст, **не** как обновляемые поля `SEQ`/`REF`. После перестановки листингов номера следует пересобрать из QMD, а не обновлять полями Word.
- Формат отдельного документа по ЕСПД, сквозная нумерация в приложениях и широкие распечатки «гармошкой» в MVP не объявлены реализованными.
