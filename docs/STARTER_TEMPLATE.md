# Новая работа и зависимости

Новая работа — отдельный стандартный проект Quarto `default`, созданный из `quarto/`. Вся содержательная часть находится в `chapters/main.qmd`; делить небольшой текст на главы не требуется. Book остаётся в `examples/book/` для многофайловой работы.

## Что получает автор

```text
Работа/
├── chapters/main.qmd     # только setup-ячейка, без учебного текста
├── metadata.yml          # незаполненные сведения
├── references.bib        # пустая библиография
├── data/, figures/       # материалы конкретной работы
├── _quarto.yml           # настройки Quarto
├── _extensions/…/academic/ # установленная версия расширения
├── .Rprofile, renv.lock, renv/ # воспроизводимые зависимости
├── tools/                # короткие точки входа
└── _output/              # результат, не исходник
```

Агент изменяет содержание, метаданные, источники и материалы работы. Служебные файлы создаёт Starter. При добавлении научных зависимостей lock-файл обновляется штатными средствами renv. Установленное расширение не редактируют для конкретной работы.

Полный учебный пример и каталог элементов находятся только в репозитории: [Workspaces/Пример/README.md](../Workspaces/Пример/README.md), [chapters/main.qmd](../Workspaces/Пример/chapters/main.qmd). Он включает все поддержанные объекты и единый расчёт R; новая работа этот текст и его библиографию не получает. Агент читает пример непосредственно из доступного репозитория.

## Работы внутри репозитория

Рекомендуемый удобный вход — корневой `ANK-DOCX.cmd`. Он повторяет организацию прежнего ANK, сохраняя стандартные проекты Quarto:

```powershell
.\ANK-DOCX.cmd setup
.\ANK-DOCX.cmd new "Моя курсовая"
.\ANK-DOCX.cmd new "Мой реферат" --profile referat-susu-17-2008
.\ANK-DOCX.cmd build "Моя курсовая"
.\ANK-DOCX.cmd list
```

Без аргументов открывается меню. Работы создаются в `Workspaces/<имя>/`; пользовательские каталоги игнорируются Git движка; `Workspaces/Пример/` является отслеживаемым исключением. Существующие папки не перезаписываются, пути вместо имени и зарезервированные имена Windows отклоняются. `new` создаёт чистый Starter и восстанавливает renv; сведения заполняет автор. `build` запускает Quarto с локальными инструментами репозитория. Результат находится в `_output/chapters/main.docx` конкретной работы. Ошибка сохраняет файлы для исправления и возвращает ненулевой код; автоматического удаления нет.

Реализация — короткий CMD и команды существующего C#-приложения, без собственного формата workspace, YAML-парсера или менеджера проектов. Внешние папки ниже остаются штатным вариантом.

## Внешняя работа после клонирования

Нужны Windows x64 и настольный Word. Из корня репозитория один раз запустите `setup-academic.cmd`. Setup получает готовое приложение с .NET Runtime и подготавливает локальные R, Quarto, SVG-конвертер и поставляемый Пример. SDK и PIA требуются только разработчику. Его PATH не устанавливается глобально; устройство окружения — [ENVIRONMENT_SETUP.md](ENVIRONMENT_SETUP.md).

Пример команд PowerShell (путь к репозиторию заменяется своим):

```powershell
New-Item -ItemType Directory -Path "D:\Учёба\Новая работа"
Set-Location "D:\Учёба\Новая работа"
& "D:\Repos\ANK DOCX\.tools\quarto-1.10.19\bin\quarto.exe" use template "D:/Repos/ANK DOCX/quarto" --no-prompt
& "D:\Repos\ANK DOCX\.tools\R\bin\Rscript.exe" --vanilla tools/install.R
```

Откройте папку работы в редакторе, заполните `metadata.yml`, напишите текст в `chapters/main.qmd`. Пустые обязательные сведения вызывают понятную ошибку; фиктивные автор, название и результаты автоматически не подставляются.

```powershell
& "D:\Repos\ANK DOCX\build-academic.cmd" "D:\Учёба\Новая работа"
```

Результат: `_output/chapters/main.docx`. Прямой `quarto render` также поддерживается при подготовленном PATH. Перед пересборкой закройте целевой DOCX.

## Профили и движок

`academic.profile` выбирает `coursework-susu-21-2008`, `referat-susu-17-2008` или `coursework-susu-04-2008`; исследовательская ВКР доступна как экспериментальный `research-susu-19-2008`. Состав листов и обязательные поля находятся в `profiles.json` расширения: курсовая получает титул, двухстраничное задание и аннотацию по СТО 21–2008; реферат — титул и аннотацию по СТО 17–2008. Данные листов, нумерация страниц и границы применимости описаны в [FRONT_MATTER.md](FRONT_MATTER.md). Отдельного языка описания или склеивания глав нет. Quarto копирует исходники Starter и устанавливает расширение штатной командой `use template`. Проектная точка входа находит обычный `_extensions/academic/` и namespaced-вариант `_extensions/<владелец>/academic/`.

Для технической курсовой укажите `academic.profile: coursework-susu-04-2008`. Этот набор использует технический титул, задание по приложению К, аннотацию с полной надписью и последующие страницы с формой 2а. Для старых работ остаются короткие имена `coursework`/`referat` и допустимые `academic.standard`; противоречащий стандарт отклоняется. Список комплектов: `ANK-DOCX.cmd profiles`. Содержательный QMD не содержит рамок или ручных номеров страниц. `academic.stamp.organization` позволяет задать краткий текст организации в штампе; по умолчанию используются краткое название вуза и группа. `academic.stamp.approver` необязателен; подписи и даты подписания не подставляются автоматически.

Служебный C# EXE устанавливается на компьютере и находится через PATH или `ACADEMIC_DOCX_SERVICE`. Исходники приложения и его тесты в работу не входят. Общая реализация расширения находится только в `quarto/_extensions/academic/`; работы получают установленные версии.

Для обновления расширения используйте `quarto add <тот же источник>`. Повторно применять Starter поверх авторского текста не нужно. Обновление расширения не обновляет `.Rprofile` и другие проектные настройки. GitHub-источник после публикации: `Lomikk/ANK-DOCX/quarto@<тег>`; текущий выпуск ещё не опубликован.

При переходе с заглушек необходимо дополнить `metadata.yml` новыми реквизитами из чистого Starter: организацией, подразделением, кратким ФИО, должностью руководителя, а для курсовой — реквизитами задания и нормоконтролера. Существующие авторские сведения автоматически не заменяются. В профиле `referat` теперь также обязателен `academic.summary`: аннотация предусмотрена СТО 17–2008.

Для расширения 0.4.3 требуется служебное приложение не ниже 0.4.4 в ветке 0.4.x: сначала обновите его через `setup-academic.cmd`, затем установленное расширение работы. Для Penrose используется pre-render из актуального Starter; старые проекты дополняются по [инструкции](PENROSE.md). Новые поля необязательны для существующего обычного оформления. Неподдержанные сочетания вида работы и стандарта вызывают диагностику.

## Почему пакеты больше не копируются

У каждой работы остаётся собственный `renv.lock` и проектная библиотека. `.Rprofile` включает штатную настройку `options(renv.config.cache.symlinks = TRUE)` до активации renv. На Windows renv использует junction-ссылки на пакеты в общем кэше, а не отдельные копии содержимого. Эта настройка действует и при запуске `Rscript --vanilla tools/install.R`, поскольку установщик явно читает `.Rprofile`.

При запуске через ANK общий кэш находится внутри репозитория, в `.tools/renv/`. Старые ссылки на кэш в профиле Windows автоматически не переносятся; исходники пользовательских работ setup не переписывает. У новой работы пакеты восстанавливаются сразу в локальный кэш.

Причина прежних сотен мегабайт: renv по умолчанию копирует пакеты между разными дисками. Проверено на Windows с проектами на `D:` и кэшем на `C:`: явное включение штатных junction работает. Версии и хэши пакетов сохраняются; изменение зависимости одной работы не заменяет пакет другой версии в соседней работе. Содержимое пакетов через ссылки вручную не правят.

Кэш должен оставаться доступным. На файловых системах без поддержки junction renv может перейти к копированию; обещание отсутствия копий относится к проверенному локальному Windows/NTFS-сценарию. Размер папки в Проводнике, следующем по ссылкам, может включать объём общего кэша. Смотрите также тип ссылок, а не только сумму файлов.

Настройка не преобразует автоматически уже существующие полные копии библиотек. Для старой работы нужно отдельно обновить `.Rprofile` и переустановить проектную библиотеку по её lock-файлу. Авторские файлы при этом не заменяются. Старые пользовательские работы в ходе разработки не перезаписываются.

## Пример и проверка

После setup полный пример собирается командой `ANK-DOCX.cmd build "Пример"`. Исходники примера и его метаданные отслеживаются Git; точки входа, окружение R и расширение устанавливаются setup из Starter и игнорируются Git.

`QuartoStarterTests` проверяет чистую новую работу, отсутствие примеров и библиотек в копируемом Starter, ссылки на общий кэш, обновление расширения без изменения авторских файлов и два профиля. Для полной интеграции тест сам переносит учебное содержание из репозитория в тестовую работу, проверяет 108/166 при изменении коэффициента, Word/SDK и отрицательные случаи метаданных.

Основания: [Quarto Starter Templates](https://quarto.org/docs/extensions/starter-templates.html), [renv package installation and cache](https://rstudio.github.io/renv/articles/package-install.html), [renv cache.symlinks](https://rstudio.github.io/renv/reference/config.html). Собственной системы хранения пакетов или менеджера шаблонов не добавлено.
