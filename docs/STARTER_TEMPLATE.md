# Единый Starter и метаданные работы

Решение по обсуждению [#2](https://github.com/Lomikk/ANK-DOCX/issues/2) и [#1](https://github.com/Lomikk/ANK-DOCX/issues/1). Один Starter находится в `quarto/`; его расширение — единственный поддерживаемый исходник оформления. Версия 0.2.0 использует заглушки сопроводительных листов и демонстрационные профили, без утверждения соответствия СТО.

## Структура и ответственность

```text
Работа/
├── _quarto.yml
├── metadata.yml
├── chapters/main.qmd
├── references.bib
├── data/
├── figures/
├── tools/academic.R
├── tools/install.R
├── AGENTS.md
├── .Rprofile
├── renv.lock
├── renv/
├── _extensions/…/academic/
└── _output/
```

Содержательная часть целиком помещается в `chapters/main.qmd`, разделы задаются обычными заголовками. Базовый тип проекта — `default`. Book был исходной заготовкой Positron, а не результатом сравнения требований. Он сохранён в `examples/book/` как штатный вариант многофайловой сборки и уже проверенных `book.appendices`; вводить собственное склеивание глав не требуется.

Название, автор и все сведения о работе объявляются в `metadata.yml`. В `_quarto.yml` находятся настройки сборки. `academic.profile` выбирает профиль; `profiles.yml` внутри расширения определяет подпись типа работы, порядок листов и обязательные для каждого листа поля. В стартовом QMD нет включений титула, задания или аннотации.

Демонстрационный `coursework` включает титул, задание и аннотацию; `referat` — титул. Этот состав служит проверке механизма, не перечнем обязательных листов СТО. Каждый лист содержит заметное слово «ЗАГЛУШКА». При отсутствии требуемых данных Lua-фильтр завершает сборку с перечислением YAML-полей. Неиспользуемая аннотация не требует `academic.summary`. Проверка происходит до записи DOCX, после исполнения вычисляемых ячеек; отдельная проверка до вычислений ещё не реализована.

## Создание и установка

Starter включает полноценную демонстрационную работу в `chapters/main.qmd`: расчёты R, все текущие виды таблиц и графики, формулы, сноску, примечания, источники и листинги. Приложения задаются стандартными заголовками `.appendix` в конце этого же файла; общий DOCX-адаптер назначает буквы, страницы и номера объектов. Каталог и способ добавления будущих элементов — [EXAMPLE_GUIDE.md](../quarto/EXAMPLE_GUIDE.md). Результаты новой проверки — [COMPREHENSIVE_EXAMPLE.md](research/COMPREHENSIVE_EXAMPLE.md).

В подготовленном терминале, из пустой папки:

```powershell
quarto use template "D:/Repos/ANK DOCX/quarto" --no-prompt
Rscript --vanilla tools/install.R
quarto render
```

Quarto копирует стартовые файлы и устанавливает расширение. GitHub-установка может добавить namespace владельца: `_extensions/Lomikk/academic/`. Проектная точка входа поддерживает локальный и namespaced-путь, отклоняя неоднозначность. `.quartoignore` явно сохраняет `.Rprofile`, `.gitignore`, `AGENTS.md` и маркеры пустых каталогов, исключая локальные библиотеки renv и сборки. Пользовательские работы могут храниться вне репозитория ANK и иметь собственный Git.

Для опубликованного Starter используется источник `Lomikk/ANK-DOCX/quarto@<тег>`. Выпуск 0.2.0 пока не опубликован. Для существующей работы `quarto add <тот же источник с выбранным тегом>` обновляет установленное расширение; заново применять Starter поверх авторских файлов не нужно.

## Как находится установленное приложение

Quarto, R и `rsvg-convert` используются штатными механизмами среды. C#-сервис — каталог self-contained публикации, установленный один раз на компьютере; его исходники не входят в работу. В PATH добавляется весь каталог публикации. Можно явно выбрать EXE через `ACADEMIC_DOCX_SERVICE`. Расширение 0.2.x проверяет версию приложения и не ищет соседний репозиторий или `../.tools/`.

При использовании локальной среды разработчика `build-academic.cmd "D:/Учеба/Работа"` передаёт проект Quarto с нужным PATH. Прямой `quarto render` требует подготовленного PATH, в том числе при запуске из редактора. Глобальные переменные и настройки компьютера setup не меняет.

Каждая работа хранит собственную версию расширения и lock-файл R. renv использует общий кэш пакетов. Это установленные зависимости; алгоритмы правятся один раз в репозитории ANK, затем выпускаются и явно обновляются в работах. Автоматической миграции старых проектов и управления несколькими версиями приложения пока нет.

## Почему нужна небольшая точка входа

Рассмотрены штатные Starter Templates, format extensions, project scripts и metadata extensions Quarto. Стартер и зависимости устанавливаются готовым `quarto use template`; YAML читает Pandoc, R-пакеты восстанавливает renv. Собственного `ank new`, YAML-парсера и системы плагинов нет.

Проба Quarto 1.10.19 с `contributes.metadata.project.post-render` разрешила путь скрипта расширения, но в каталоге с пробелом Windows попыталась запустить `D:\Repos\ANK` вместо полного пути. Поэтому Starter содержит короткий `tools/academic.R`: он находит единственное установленное `academic`, вызывает общий `setup.R` при source и `finalize.R` при запуске hook. Самих алгоритмов оформления в нём нет. Hook использует стабильный относительный путь проекта.

## Приёмка

`QuartoStarterTests` создаёт независимые проекты во временной папке с пробелами и кириллицей штатным `quarto use template`. Проверяет включение скрытых настроек и инструкции, исключение локальной библиотеки renv, две композиции листов, namespaced-установку, отсутствие ненужного summary у реферата, явные ошибки обязательного поля и неизвестного профиля, R-вычисление, таблицу, OMML, нативные REF и схему готового DOCX после Word. Сервис находится через PATH без `ACADEMIC_DOCX_SERVICE` дочернего процесса.

Дополнительная проверка сохранённого Book-примера и приложений выполняется после обновления его установленного расширения командой setup. Новые результаты и фактические ограничения см. в [отчёте](research/STARTER_TEMPLATE_ACCEPTANCE.md).

Официальные основания: [Starter Templates](https://quarto.org/docs/extensions/starter-templates.html), [Distribution](https://quarto.org/docs/extensions/distributing.html), [Project Scripts](https://quarto.org/docs/projects/scripts.html), [Metadata Extensions](https://quarto.org/docs/extensions/metadata.html), [Working Dir](https://quarto.org/docs/projects/code-execution.html#working-dir). Проверены документация и исходники установленного Quarto 1.10.19.
