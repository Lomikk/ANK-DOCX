# Приёмка единого Starter 0.2.0

Позднее Starter дополнен полноценной учебной работой, а `.appendix` поддержан в одном `main.qmd`; новые результаты находятся в [COMPREHENSIVE_EXAMPLE.md](COMPREHENSIVE_EXAMPLE.md). Ниже сохранена приёмка первоначального выделения минимального Starter.

Дата: 29 октября 2026 года. Решение и команды описаны в [STARTER_TEMPLATE.md](../STARTER_TEMPLATE.md). Новый выпуск пока не опубликован; проверка выполнена на локальных исходниках.

## Что изменено

- `quarto/` содержит один Starter для всех работ и единственный исходник `_extensions/academic/`. Новые проекты — стандартный Quarto `default` с содержательным входом `chapters/main.qmd`. Сведения о работе, включая название и автора, находятся в `metadata.yml`.
- `academic.profile` выбирает состав из `profiles.yml` расширения. `coursework` включает заглушки титула, задания и аннотации; `referat` — титула. Все листы явно обозначены как заглушки. Соответствие состава СТО не заявляется.
- Pandoc читает стандартный YAML профилей. Обязательные поля определяются подключёнными листами; неизвестный профиль и отсутствующие поля дают ненулевое завершение. Проверка выполняется до записи DOCX, после расчётов.
- Сервис 0.2.x находится через PATH или явный `ACADEMIC_DOCX_SERVICE`; ссылка на соседний `../.tools/` удалена. Приложение сообщает версию, расширение проверяет совместимость.
- Прежний Book перенесён в `examples/book/`, отдельные образцы — в `examples/objects/`. Его расширение и короткая точка входа устанавливаются setup из Starter, игнорируются Git и не являются вторым поддерживаемым исходником. Приложения находятся в `examples/book/chapters/` и подключаются штатным Quarto-профилем `appendices`.

`QuartoStarterTests` содержит один интеграционный тест, последовательно охватывающий обе работы и отрицательные случаи. Namespaced-путь проверен локальным перемещением установленной зависимости в структуру GitHub; сетевое создание из ещё не опубликованного тега не проверено. В Word-проверке нативный менеджер библиографии отмечен как skipped: здесь используется Citeproc.

## Выявленные риски и исправления

1. `contributes.metadata.project.post-render` Quarto 1.10.19 неверно запустил путь с пробелом Windows. Вместо нового механизма сборки оставлена небольшая проектная точка входа `tools/academic.R`; реализация оформления остаётся в расширении.
2. Pandoc запускается рядом с QMD. Служебные JSON теперь записываются через публичный `quarto.project.offset` в корневой `.quarto/`, без зависимости от положения главы и без преобразования полного кириллического пути через окружение Lua.
3. В окружении фильтра Quarto вызов `error()` оказался логированием с продолжением сборки. Отрицательный тест это выявил; для прекращения используется стандартный Lua `assert`. Тот же способ сохранён для ошибок входов приложений.
4. Старый тест паритета редактора сравнивал новый живой reference-docx со снимком до изменения шрифта листингов. Сам reference-docx при переносе не изменялся: Git blob `bd1944e6d69b5b9fca48aae7ee3f5c3225cd486d`. Для исторического паритета выделен фиксированный вход из `d793414`; ожидаемый legacy-файл оставлен неизменным. Подробности — в [описании фикстур](../../tools/AcademicDocx.Tests/Fixtures/README.md).

## Сохранённые ограничения

Полная готовая сборка требует настольного Word на Windows. Ненулевые ошибки схемы промежуточного пакета не исправлены выделением Starter. Не проверены установка на чистой машине, автоматическая миграция старых работ, управление несколькими установленными версиями сервиса и нормативные образцы листов. Достаточность `default` для полного будущего сценария приложений внутри единственного main.qmd пока не доказана: подтверждённая реализация приложений использует стандартный Book.

Bundle `ANK-DOCX-appendices.bundle` уже был применён до начала изменений: его `0093eeced887982246878c7524f4b20411c427c0` совпадал с HEAD и origin/main. Повторное применение не выполнялось. Существовавшие пользовательские процессы Word не завершались; старые заблокированные результаты `academic/_book/` сохранены.

Автоматическая проверка отклонила удаление временных тестовых проектов с причиной `blocked by policy`. Они сохранены обратимым перемещением в локальном `archive/starter-test-runs-2026-10-29/`; копии результатов и журналов остались в `build/starter-qa/`.
