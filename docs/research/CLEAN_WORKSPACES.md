# Чистая работа и общий кэш пакетов

30 октября 2026 года. Принятое разделение: авторские материалы в работе, учебные примеры и разработка в репозитории ANK. Создание и обновление остаются штатными операциями Quarto; зависимости управляются renv.

## Выбор решения

Повторный обзор экосистемы не выполнялся. Проверены официальные документы [Quarto Starter Templates](https://quarto.org/docs/extensions/starter-templates.html), [renv package installation](https://rstudio.github.io/renv/articles/package-install.html) и [renv config](https://rstudio.github.io/renv/reference/config.html), а также установленный код renv 1.3.1 (`renv_cache_config_symlinks`, `renv_cache_linkable`, `renv_file_link`).

Quarto копирует только каталог Starter `quarto/`. Полный пример перенесён в `examples/reference/`, за пределы копируемого дерева. В Starter нет учебного текста, модельных данных и учебной библиографии; `main.qmd` содержит только setup-ячейку и комментарий. Метаданные незаполнены. Каталог примера остаётся в README самого примера, инструкция агента ссылается на него в репозитории.

Сохранены стандартные `_quarto.yml`, установленное `_extensions/` и проектный lock-файл. Общая реализация расширения не правится в работах: устанавливается её версия. Проверено, что `quarto add` не меняет содержательный QMD и metadata.yml. Прямые пути из работы в соседний репозиторий, собственный реестр шаблонов и собственный менеджер зависимостей не вводились.

## Почему раньше было около 392 МБ

В обследованной пользовательской работе `renv/` занимал 384,33 МиБ; содержательные и служебные исходники были меньше 1 МиБ. Проект находится на D:, глобальный кэш renv — на C:. По умолчанию renv на Windows разрешает ссылки на кэш только для одного диска, иначе копирует пакеты.

Штатная настройка `options(renv.config.cache.symlinks = TRUE)` в `.Rprofile`, до активации renv, включает junction и в этом сценарии. Установщик `Rscript --vanilla tools/install.R` явно читает `.Rprofile`, поэтому настройка не теряется при `--vanilla`. Узкая проба одного jsonlite и затем полное восстановление подтвердили junction между D: и C:. Собственных ссылок или операций с содержимым кэша код ANK не создаёт.

Версии каждой работы остаются в собственном renv.lock. Ссылки ведут на записи кэша с версией и хэшем. Изменять файлы пакетов через проектные ссылки нельзя. Существующие полные копии библиотек автоматически не преобразуются; пользовательские проекты в этом изменении не перезаписывались. На средах без junction renv может перейти к копированию. Размер, подсчитанный с обходом целей ссылок, не отражает отдельное потребление места каждой работой.

## Приёмка

Проверены Windows, Quarto 1.10.19, R 4.6.1, renv 1.3.1, SDK 3.3.0 и Word 16.0.20326.

- Две работы созданы `quarto use template` в каталоге с кириллицей и пробелами. До заполнения подтверждены чистый main, пустая библиография, отсутствие examples, каталога примера, библиотек renv, исходников приложения и docs.
- В обеих работах восстановлены 84 пакета через junction на общий кэш; отдельно находится bootstrap renv. У jsonlite в двух проектах одинаковая цель ссылки на C:.
- Свои файлы библиотеки занимают 3,328 МиБ. Чистая работа с восстановленными зависимостями — 3,646 МиБ без результатов и промежуточных сборок. После добавления полного учебного содержания и сборки каждая тестовая работа имеет около 5,85 МиБ собственных файлов. Кэш считается отдельно один раз.
- Для полной проверки тест явно заполняет работы материалом примера из репозитория. Коэффициенты 3/5 дают 108/166. Сохранены профили, приложения, OMML, SVG, сноска, ссылки, отсутствие summary у реферата и ошибки обязательных полей/неизвестного профиля. Курсовая — 14 страниц, реферат — 12; итоговые DOCX имеют 0 ошибок SDK.
- Полный пример отдельно установлен setup и собран командой `build-academic.cmd examples/reference`: 14 страниц, 0 ошибок SDK. Его runtime-файлы устанавливаются из Starter и игнорируются Git, исходники примера отслеживаются.
- Отдельная минимальная работа с одним введением и пустой библиографией собрана без учебного содержания: 5 страниц, включая заглушки и оглавление, 0 ошибок SDK.
- 15 переносимых тестов прошли; 6 групп дополнительных Word/CLI-проверок в этом запуске отключены. Интеграционный сценарий двух Starter-проектов включён явно и прошёл отдельно. Тесты прежнего разделения таблиц повторно не запускались: алгоритм не менялся.

## Корневой CMD и Workspaces

По следующему запросу пользователя добавлен привычный сценарий старого ANK: `ANK-DOCX.cmd`, меню без аргументов и игнорируемый `/Workspaces/`. Старый репозиторий AutoNormoKontrol прочитан как образец, не изменялся. Команды: `setup`, `new NAME [--profile coursework|referat]`, `build NAME`, `list`.

CMD делегирует существующему приложению C#, которое запускает стандартные Quarto и renv без shell-строк из названий работ. Версия локального Quarto читается из dependencies.lock.json. Нового формата проекта, парсера QMD и собственного конвейера не добавлено. Существующая папка не перезаписывается; пути вместо имени, служебные имена Windows и неизвестный профиль отклоняются. При ошибке файлы сохраняются, дочерняя диагностика показывается, возвращается ненулевой код.

Корневым CMD созданы две чистые работы с кириллицей и пробелами, проверены профили, общий кэш, меню, список и Git-ignore. После явного заполнения минимального текста и метаданных обе собраны той же командой: курсовая — 5 страниц, реферат — 3; SDK — 0 ошибок, собственные процессы Word завершены. Повторное создание существующей работы отклонено без изменения файлов. Неизвестный профиль не создаёт папку. После приёмки собственные тестовые работы перемещены в `.tools/workspace-cli-acceptance/`, пользовательский список Workspaces остаётся пустым.

11 CLI-проверок прошли, включая защиту авторских файлов и отказ от выхода за каталог Workspaces. Свидетельства: [CLI](evidence/workspace-cli/cli.trx), [курсовая](evidence/workspace-cli/coursework-finalize.json), [реферат](evidence/workspace-cli/referat-finalize.json). Проверки основного учебного примера выше не подменяются этими минимальными работами.

## Поставляемая работа в Workspaces

В последующем уточнении пользователь выбрал `Workspaces/Пример/` местом единственного полного примера. Исходник перенесён туда из `examples/reference/`, второй поддерживаемой копии нет. Описанные выше измерения до переноса сохраняют прежние пути как историю проверки.

Корневой `.gitignore` использует `/Workspaces/*` и исключение `!/Workspaces/Пример/`. Локальный `.gitignore` примера исключает установленное расширение, окружение R, точки входа и результаты. В Git включаются только QMD, YAML, библиография, каталог и правила игнорирования. Пользовательские работы, в том числе созданные во время изменения, не затронуты.

Setup устанавливает зависимости примера по новому пути; `ANK-DOCX.cmd list` показывает его среди работ, `ANK-DOCX.cmd build "Пример"` собирает 14 страниц с 0 ошибками SDK. Повторный `new "Пример"` отклоняется без изменений. Новые работы продолжают получать чистый Starter и не копируют содержимое примера.

Проверка после переноса: [Git-ignore](evidence/shipped-example/git-ignore.json), [финализация примера](evidence/shipped-example/finalize.json), [повторный сценарий двух работ](evidence/shipped-example/starter-retry.trx). Первая попытка дала 11 успешных CLI-проверок и прервалась на сетевой загрузке bootstrap renv; [отчёт](evidence/shipped-example/first-attempt.trx) сохранён. Повторный сценарий успешно прошёл оба профиля и отрицательные случаи за 3 мин 21 с. Основное приложение обновлено после закрытия открытого меню пользователем.
