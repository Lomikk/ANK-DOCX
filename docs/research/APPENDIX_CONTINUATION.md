# Виды и продолжения приложений НИР

31 октября 2026 года, расширение и сервис 0.4.2. Для экспериментального `research-susu-19-2008` реализованы общий заголовок «ПРИЛОЖЕНИЯ», виды обязательное/информационное, надписи продолжения и записи оглавления. Авторский интерфейс — [APPENDIX_RULES.md](../APPENDIX_RULES.md#особенности-нир-сто-19).

## Основание и выбор механизма

СТО ЮУрГУ 19–2008, пп. 6.12.1–6.12.3: первый лист первого приложения содержит общий заголовок, последующие листы — надпись продолжения справа вверху; приложения делятся на обязательные и информационные. Использованы уже разобранные источники старого ANK: `sources/susu/sto-19-2008/derived/standard.layout.txt` и `resources/styles/susu-appendices.sty`, checkout `be77d1c`. Оттуда сохранён выбранный информационный вид по умолчанию. Старый TeX и универсальная система правил не переносились.

Сначала рассмотрены штатные средства Word. [Особый первый колонтитул раздела](https://learn.microsoft.com/en-us/office/vba/api/word.pagesetup.differentfirstpageheaderfooter) позволяет пропустить надпись на первом листе приложения и повторять её дальше без определения разрывов собственным пагинатором. [TablesOfContents.MarkEntry](https://learn.microsoft.com/en-us/office/vba/api/word.tablesofcontents.markentry) создаёт штатную запись TC; [UseFields](https://learn.microsoft.com/en-us/office/vba/api/word.tableofcontents.usefields) и [TableID](https://learn.microsoft.com/en-us/office/vba/api/word.tableofcontents.tableid) подключают эти записи к оглавлению. Применены эти готовые механизмы.

Собственный код ограничен связью стандартного заголовка QMD с видом приложения, разметкой строк, настройкой разделов и вызовом API Word. Параметр `appendix-layout` находится в едином `profiles.json`. Базовое оформление остальных профилей использует тот же `AppendixFormatting`; для него сохранены прежние обозначение и название без новых видов и колонтитулов. Научные таблицы, вычисления, SEQ/REF и общие счётчики имеют одну реализацию.

Первоначально созданные напрямую SDK поля TC присутствовали в OOXML и распознавались Word, но не попадали в сохранённое оглавление. Они заменены публичным `MarkEntry`, а при обновлении оглавления явно выбираются TC и идентификатор `A`. Наличие поля само по себе больше не считается успехом: финализатор проверяет записи приложений в фактическом результате оглавления. В диагностике TC не запрашивается недоступный для него отображаемый `Result`.

## Проверенный корпус

[appendices.qmd](../../tools/AcademicDocx.Tests/Fixtures/appendices.qmd) включён в обычный Starter с условными реквизитами НИР. Приложение А обязательное, содержит вычисляемую R/flextable таблицу на 90 строк; приложение Б информационное по умолчанию, содержит длинный текст. Quarto 1.10.19, R 4.6.1, Word 16.0.20326, Open XML SDK 3.3.0.

- Сборка исходника Quarto и финализация подготовленного пакета актуальным сервисом дали **13 страниц, 0 ошибок SDK** после сохранения Word. До нормализации сохраняется известное ограничение промежуточного пакета (1097 ошибок), готовый DOCX требует Word.
- Первые страницы приложений — **8 и 11**: нет надписи продолжения, вид и название стоят под обозначением. Общий заголовок присутствует один раз на странице 8.
- Страницы **9–10** содержат «Продолжение приложения А», **12–13** — «Продолжение приложения Б». Надпись находится в верхнем колонтитуле справа; текст и таблица её не перекрывают.
- Общая таблица разделена штатным адаптером на три фрагмента с повторяемой шапкой; страницы 9/10 содержат «Продолжение таблицы А.1» / «Окончание таблицы А.1». Сохранённое поле REF возвращает **А.1**.
- Сохранённое оглавление содержит обозначения и названия А/Б со страницами **8/11**, без строк вида. Статистика реферата: **13 страниц, 0 рисунков, 1 таблица, 1 источник, 2 приложения**. Печатные номера основной части и приложений непрерывны, 5–13.
- Повторная финализация уже нормализованного DOCX прошла с теми же 13 страницами, двумя приложениями и нулём ошибок SDK. Нет дублирования общего заголовка, строк вида, TC и разделов.
- Семь целевых SDK-тестов прошли: базовое/исследовательское оформление, повторное применение, сохранение авторского текста, схема, колонтитулы и счётчики. Проверка четырёх профилей Lua/Pandoc также прошла.
- PDF экспортирован из Word; просмотрены все страницы, отдельно страницы начала приложения и продолжения таблицы. Собственные процессы Word закрылись без ошибок.

Журналы — [evidence/appendix-continuation/](evidence/appendix-continuation/). Временные проекты, DOCX, PDF и изображения находятся в `.tools/appendix-continuation/` и не поставляются новым работам.

## Границы

Новые виды и колонтитулы включены только у НИР СТО 19. Их сочетание с техническими рамками не поддержано этой приёмкой. Подразделы приложений, формулы и листинги сохраняют ограничения общего механизма. Полный Word-корпус проверен для одного `main.qmd`; Book передаёт те же данные приложений, но отдельный многостраничный Book в этом изменении не пересобирался. При изменении состава приложений нужна сборка Quarto для назначения букв; содержание и подписи не проверяются на научную полноту. Полное соответствие СТО 19 не заявляется.
