# Локальная среда сборки ANK

Пользователю нужны Windows x64, настольный Word и шрифты работы. Git и редактор устанавливаются в системе. Подготовка из корня клона:

Обычный запуск — `ANK-DOCX.cmd` без аргументов: первый запуск предлагает установить зависимости, затем открывается меню. Создание, сборка, открытие папки и документа доступны через выбор пунктов. Команды ниже сохранены для автоматизации:

```cmd
ANK-DOCX.cmd setup
ANK-DOCX.cmd new "Курсовая"
ANK-DOCX.cmd build "Курсовая"
```

`setup` получает готовый C#-сервис с .NET Runtime, проверяет SHA-256 архива и распаковывает его в `.tools/academic-docx/`. .NET SDK и Word PIA пользователю не нужны. Далее C# устанавливает закреплённые R, Quarto и SVG-конвертер, проверяет версии и подготавливает поставляемый Пример. Повторный запуск использует установленные инструменты и восстанавливает пакеты по lock-файлу. Частично скачанный архив не считается готовым.

| Место | Содержимое |
|---|---|
| Git | Исходники, Starter, формы, reference DOCX, CSL, XML рамок, инструкции и lock-файлы |
| `.tools/academic-docx/` | Готовое приложение, библиотеки, собственный .NET Runtime и уведомления о лицензиях |
| `.tools/R/`, `.tools/quarto-*/`, `.tools/rsvg-convert-*/` | Локальные инструменты |
| `.tools/node-v*-win-x64/`, `.tools/penrose/`, `.tools/npm-cache/` | Локальный Node.js, Penrose и кэш npm; SVG собираются автоматически по [правилам](PENROSE.md) |
| `.tools/renv/` | Состояние renv, кэш установленных пакетов и загрузок |
| `.tools/downloads/` | Архивы и установщик R; их можно скачать заново |
| Система | Word, шрифты, Git, редактор; у разработчика также SDK и официальные PIA |

`.tools/` не входит в Git и не копируется в новые работы. Каждая работа имеет собственный `renv.lock` и штатную библиотеку renv со ссылками на общий кэш. `LocalToolchain` задаёт пути только дочерним процессам setup/new/build; системный PATH и профиль пользователя R не изменяются. Для запуска локального R из редактора setup создаёт `Renviron.site` внутри своей установки R. Выбирать в редакторе нужно этот R, а не другую системную установку.

Quarto включает собственный Pandoc; отдельная установка Pandoc не нужна. Обнаруженное ограничение Lua-загрузчика Quarto/Pandoc на Windows обойдено стандартной junction-ссылкой в TEMP. Она отдельная для каждого каталога установки, проверяется перед повторным использованием и указывает на локальную `.tools/quarto-…/`. Сами программы остаются в клоне. Эта же общая реализация заменяет прежний обход в Book-скрипте. Текущему обходу требуется доступный TEMP с путём из ASCII; при другом пути выдаётся диагностика.

Существующие пользовательские работы setup не обновляет. Ранее созданные ссылки на внешний кэш могут сохраниться: обычный restore оставляет уже совпадающие версии. Перенос выполняется отдельно в активном локальном окружении: `renv::remove` удаляет выбранные пакеты только из проектной библиотеки, затем `renv::restore` восстанавливает её по сохранённому lock-файлу в новый кэш. Старый общий кэш и исходники не удаляются. После переноса каталога на другой компьютер могут потребоваться восстановление инструментов и ссылок; это не обещание полностью переносимого окружения. Временные файлы Windows/Word остаются в штатных временных каталогах.

## Разработка и выпуск

```cmd
setup-academic.cmd --development
build-service.cmd
pack-service.cmd
```

Режим разработчика компилирует приложение и дополнительно устанавливает зависимости Book-примера. `build-service.cmd` только публикует приложение; `pack-service.cmd` создаёт `.tools/releases/academic-docx-<версия>-win-x64.zip` и обновляет `tools/service-release.cmd` с версией, адресом выпуска и SHA-256. Этот небольшой файл читается штатным CMD, отдельного JSON/YAML-парсера в начальном загрузчике нет. Основные версии инструментов остаются в `dependencies.lock.json`.

Архив распространяется через GitHub Release с соответствующим тегом. До публикации его можно проверить локально: задать `ANK_DOCX_SERVICE_ARCHIVE` полным путём к архиву и запустить setup; проверка закреплённого SHA-256 обязательна и для локального файла. `setup-academic.cmd --service-only` устанавливает только сервис, без R и проверки Word. Это также режим приёмки первоначального запуска без SDK.

Публикация релиза — отдельное действие: создание архива локально не загружает файлы в GitHub и не отправляет коммиты. Сначала проверяют архив, затем публикуют его вместе с соответствующими исходниками и манифестом. Переупаковка изменённой сборки требует нового согласованного выпуска.

Основа: штатная [публикация .NET self-contained](https://learn.microsoft.com/en-us/dotnet/core/deploying/), Windows `curl`/`tar`/`certutil`, [пути состояния renv](https://rstudio.github.io/renv/reference/paths.html) и [кэш пакетов renv](https://rstudio.github.io/renv/articles/package-install.html). Собственный менеджер пакетов и собственный формат авторских исходников не добавлены.

Интерактивное меню сервиса 0.4.5 использует готовые `SelectionPrompt` и `TextPrompt` из [Spectre.Console 0.57.2](https://www.nuget.org/packages/Spectre.Console/), лицензия MIT поставляется с сервисом. Библиотека отвечает за стрелки, Esc, прокрутку и перерисовку; собственный терминальный движок не добавлен. При перенаправленном вводе/выводе используется простой выбор по номерам, EOF завершает меню. Подписи и описания доступных комплектов читаются из общего `profiles.json`; меню не расширяет список поддерживаемых стандартов.
