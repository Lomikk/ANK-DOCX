# Диаграммы Penrose

Penrose используется для схем и отношений между объектами; численные научные графики сохраняют обычный путь ggplot2. Официальный CLI `@penrose/roger` устанавливается командой `ANK-DOCX.cmd setup` вместе с локальным Node.js. Бинарные файлы, npm-пакеты и кэш находятся в `.tools/`, в Git хранятся версии и npm lock-файл. Системный Node.js и глобальная установка npm-пакета не требуются.

## Исходники отдельно от текста

Принятый способ — отдельная папка диаграммы и обычная ссылка на рисунок в QMD:

```text
figures/penrose/sets/
  diagram.domain
  diagram.substance
  diagram.style
  diagram.trio.json
```

- `.domain` задаёт типы объектов и отношений.
- `.substance` описывает конкретные объекты и связи.
- `.style` задаёт геометрию, подписи и ограничения размещения.
- `.trio.json` связывает файлы и сохраняет `variation` для повторяемой компоновки.

Это стандартные форматы Penrose. Несколько диаграмм могут ссылаться на общие Domain/Style, копировать их в каждую папку не обязательно. Собственного синтаксиса блоков Penrose в QMD нет.

Пример штатного `.trio.json`:

```json
{
  "domain": "diagram.domain",
  "substance": "diagram.substance",
  "style": ["diagram.style"],
  "variation": "ANK-example-sets-2026"
}
```

В `chapters/main.qmd` остаются подпись и ссылка:

```qmd
На рисунке [-@fig-sets] показаны отношения между множествами.

![Отношения между множествами](../.quarto/penrose/sets/diagram.svg){#fig-sets width=80%}
```

Рядом с `diagram.trio.json` может находиться **`diagram.edited.svg`** — сохранённый результат правки. Это обычный SVG, а не признак блокировки рисунка. Если он существует, сборка использует его и не запускает Penrose для этой диаграммы. Исходники могут меняться независимо, но их новая генерация применяется отдельной командой.

При сборке штатный `project.pre-render` Quarto вызывает `tools/academic.R diagrams`. Общий скрипт расширения обрабатывает `.trio.json` под `figures/penrose/` и сохраняет SVG с тем же относительным деревом в `.quarto/penrose/`. Если диаграмм нет, шаг ничего не рендерит. При ошибке CLI сборка прекращается: прежний SVG не используется как успешный результат.

Затем обычный механизм Quarto/Pandoc вставляет SVG, а общий адаптер ANK формирует подпись, SEQ/REF и статистику. Для совместимости с Word `rsvg-convert` переводит текст SVG в векторные контуры: Word не сохранял размер букв из CSS-сокращения `font`, создаваемого Penrose. Результат остаётся векторным; геометрия и надписи редактируются в исходниках Penrose.

## Использование

```cmd
ANK-DOCX.cmd setup
ANK-DOCX.cmd build "Пример"
```

Вне полной сборки можно вызвать официальный CLI через локальное окружение:

```cmd
ANK-DOCX.cmd penrose trio --trio "путь/diagram.trio.json" --out "путь/diagram.svg"
```

Такой вызов создаёт исходный SVG Penrose; совместимость Word обрабатывает pre-render при сборке. Авторские файлы агента находятся в папке диаграммы, SVG в `.quarto/` генерируются заново и в Git не добавляются. После изменения связей или Style агент должен посмотреть полученную картинку: ограничения размещения не проверяют правильность научного содержания.

Новые работы получают pre-render из Starter. Для старой работы нужны обновлённое расширение, точка входа `tools/academic.R` из Starter и настройка:

```yaml
project:
  pre-render:
    - tools/academic.R diagrams
```

Эта строка дополняет существующий блок `project`, не создаёт второй. Минимальные версии: расширение 0.4.3 и сервис 0.4.4. Пользовательские проекты автоматически не переписываются.

Проверенные версии — Node.js 24.22.2, roger 3.3.1. Особенности зависимостей и приёмка — [PENROSE_INTEGRATION.md](research/PENROSE_INTEGRATION.md). Официальные источники: [CLI и форматы](https://penrose.cs.cmu.edu/docs/ref/using), [исходники и MIT-лицензия](https://github.com/penrose/penrose), [pre-render Quarto](https://quarto.org/docs/projects/scripts.html).


## Локальный редактор и сохранение правок (сервис 0.4.12, расширение 0.4.9)

В меню ANK-DOCX.cmd выберите **Рисунки Penrose → работу → Открыть локальный редактор**.
При первом открытии устанавливается официальный редактор 3.3.1 из закреплённого исходника
и npm lock-файла. Нужен интернет для этой установки. В дальнейшем интерфейс и обработка
диаграмм работают локально. Интернет нужен только необязательным функциям upstream,
например входу GitHub, публикации или внешним ссылкам; для нашей работы они не требуются.

CMD запускает Vite с официальным интерфейсом и `roger watch` для `figures/penrose/`
выбранной работы. Браузер по умолчанию открывает `http://127.0.0.1:3000/try/`.
Во вкладке **roger**, поле **trio**, выберите диаграмму, затем Compile.
В Settings включите **Interactive Mode → Edit Mode**. Доступные для перемещения фигуры
можно перетаскивать; редактирование и оптимизация — штатные возможности Penrose.

После правок:

1. Откройте **Import / Export**, выберите **Рисунок в работе** и нажмите
   **Сохранить SVG и Trio в работу**. При выборе исходного trio назначение подставляется автоматически.
2. Дождитесь сообщения **SVG и Trio сохранены в работу**. Скачивать и переносить файлы не нужно.
3. Выберите **Собрать DOCX**. Редактор может оставаться открытым во время применения и сборки.
4. При выходе из меню рисунков редактор и Roger останавливаются. При следующем открытии
   они запускаются заново. Порты 3000 и 9160 должны быть свободны; другое приложение
   или другая работа на этих портах не завершаются принудительно.

**Обычная сборка не изменяет `*.edited.svg`.** Она переводит этот файл в совместимый с Word
SVG под `.quarto/penrose/`. Поэтому прежние ссылки QMD остаются правильными, ручные правки
не исчезают при очистке `.quarto/` или обновлении расширения. Содержимое сохранённого SVG
можно редактировать и агентом, если это входит в задачу пользователя.

При применении новой версии предыдущая копируется в `.history/` рядом с рисунком.
Чтобы вернуть автоматическую генерацию, используйте **Сгенерировать рисунок заново**.
Команда сначала успешно строит и проверяет новый вариант, а затем переносит сохранённый
рисунок в историю. Ошибка генерации сохраняет действующий `*.edited.svg`. Старую версию
можно вернуть обычной командой применения SVG из истории.

Команды из корня (ID — путь без `.trio.json`, относительно `figures/penrose/`):

```cmd
ANK-DOCX.cmd figures "Управление данными"
ANK-DOCX.cmd figures "Управление данными" list
ANK-DOCX.cmd figures "Управление данными" open
ANK-DOCX.cmd figures "Управление данными" apply "conceptual/diagram" "C:\Users\user\Downloads\diagram.svg"
ANK-DOCX.cmd figures "Управление данными" generate "conceptual/diagram"
```

`open` открывает редактор и ждёт Enter для завершения сессии. Интерактивное меню позволяет
применять SVG и собирать работу, не закрывая редактор. Для подготовки установки отдельно:
`figures NAME setup`. Для диагностики без открытия браузера: `figures NAME serve`.
`figures NAME prepare` создаёт дополнительный локальный HTML-каталог с превью и SVG,
содержащими исходники для штатного Import/Upload. Основной способ выбора рисунка — список trio
в локальном редакторе. Штатная кнопка Save сохраняет браузерную рабочую область;
для документа используйте добавленную кнопку **Сохранить SVG и Trio в работу**.
Экспорт **Penrose SVG** и команда `apply` остаются альтернативным способом.

Кнопка сохраняет текущий SVG как `diagram.edited.svg`, три текста как
`diagram.saved.domain`, `diagram.saved.substance`, `diagram.saved.style` рядом с trio
и обновляет ссылки и variation в `diagram.trio.json`. Общие библиотеки не перезаписываются.
Перед записью официальный CLI проверяет исходники, rsvg проверяет SVG. Предыдущие файлы
и используемые ими исходники сохраняются в ZIP под `.history/`; ошибка проверки оставляет
рабочие файлы без изменений. После изменения текста сначала нажмите Compile.
Локальный API привязан к сессии и разрешает сохранение только в рисунки выбранной работы.

### Ограничения штатного редактора

- Визуальное перемещение не обязано изменять Domain/Substance/Style. Экспорт SVG сохраняет
  готовый рисунок. Повторный импорт SVG или открытие trio компилирует исходники заново;
  прежние перемещения мышью могут не восстановиться. Рабочий рисунок в DOCX при этом сохранён.
- Элемент с вычисляемыми координатами нельзя свободно перетаскивать. При создании Style
  используйте свободные входы и цели там, где требуется перетаскивание. Строки таблицы,
  например, обычно удобнее перемещать вместе с блоком таблицы.
- Общая библиотека Style в нескольких файлах поддержана Roger. При сохранении из браузера
  объединённый Style становится отдельным файлом выбранного рисунка; остальные рисунки
  продолжают использовать прежнюю общую библиотеку.
- Upstream не публикует npm-пакеты editor/examples. Мы запускаем закреплённый официальный
  исходник через небольшую локальную конфигурацию Vite с опубликованными core/components.
  Онлайн-галерея примеров отключена: рисунки работы выбираются через Roger.
- Два подтверждённых адаптационных изменения: привязка watch только к 127.0.0.1 с проверкой Origin локального редактора и исправление
  AND/OR-проверки устаревшего обработчика `trio_file` в RogerPanel, иначе агрегированный
  ответ `trio_files` передавал неопределённые имена файлов. Версии и сборка описаны в
  `tools/PenroseEditor/README.md`. Это не новый редактор или оптимизатор.

### Правило совместной работы

Ручная правка не блокирует диаграмму и не требует дополнительных согласований при каждой
сборке. При задаче изменить саму модель агент проверяет наличие `*.edited.svg` (`figures NAME list`),
готовит новую версию и применяет её либо вызывает generate в рамках уже поставленной задачи.
Предыдущая версия сохраняется в истории, итоговый рисунок проверяется визуально. Если
пользовательскую компоновку пришлось изменить, это кратко отмечается в результате.
Не удаляйте сохранённый рисунок только для того, чтобы прошла обычная сборка.

У существующей работы один раз обновите установленное расширение штатным `quarto add`
из актуального `quarto/`. Установленные `_extensions/` вручную не редактируют.
Пользовательский выпуск сервиса с этими командами ещё не опубликован; в этом checkout
разработчик собирает 0.4.13 командой `tools\build-service.cmd`.
