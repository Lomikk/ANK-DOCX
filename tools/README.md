# Служебные инструменты ANK DOCX

Обычный пользователь запускает [ANK-DOCX.cmd](../ANK-DOCX.cmd) в корне репозитория. Скрипты рядом с этим README нужны для установки, разработки и диагностики; в каждом есть короткий комментарий о назначении.

Все команды ниже выполняются из корня репозитория. Папку установки скрипты находят относительно своего файла. Относительные пути входных документов и проектов считаются от текущего каталога терминала.

| Файл | Назначение | Пример команды из корня |
|---|---|---|
| [setup-academic.cmd](setup-academic.cmd) | Скачать готовый сервис и подготовить зависимости в `.tools/`. `--service-only` устанавливает только сервис; `--development` компилирует его и подготавливает также Book-пример. | `tools\setup-academic.cmd` |
| [academic-docx.cmd](academic-docx.cmd) | Прямой вызов движка: справка, проверка DOCX, диагностика Word, экспорт PDF. Финализацию обычной работы запускает Quarto автоматически. | `tools\academic-docx.cmd help` |
| [build-academic.cmd](build-academic.cmd) | Собрать проект по указанному пути с локальными инструментами. Без пути собирает интеграционный `examples/book/`; принимает параметры Quarto. | `tools\build-academic.cmd "D:\Учёба\Курсовая"` |
| [build-service.cmd](build-service.cmd) | Скомпилировать C#-движок в `.tools/academic-docx/`. Нужны .NET SDK и официальные PIA; R-окружение не восстанавливает. | `tools\build-service.cmd` |
| [pack-service.cmd](pack-service.cmd) | Собрать сервис, создать ZIP в `.tools/releases/` и обновить версию, URL и SHA-256 в `service-release.cmd`. Загрузка в GitHub выполняется отдельно. | `tools\pack-service.cmd` |
| [service-release.cmd](service-release.cmd) | Данные опубликованного сервиса для установщика. Генерируется упаковщиком, самостоятельно запускать не требуется. | — |

В PowerShell добавляйте `.\` перед командой: например, `.\tools\academic-docx.cmd --version`.

## Для агента и разработчика

- Создавайте и собирайте работы через корневой `ANK-DOCX.cmd`; прямые команды используйте для конкретной задачи разработки или диагностики.
- Исходники движка — `AcademicDocx/` и `AcademicDocx.Core/`, проверки — `AcademicDocx.Tests/`; npm-манифест Penrose — `Penrose/`.
- Бинарные файлы, runtime и кэши находятся в корневой `.tools/` и не входят в Git. Папка `tools/` содержит поддерживаемые исходники и точки входа.
- После изменения расположения скриптов проверяйте первый запуск и вызовы из другого текущего каталога. Не возвращайте служебные дубликаты в корень.
- Исторические отчёты в `docs/research/` могут содержать прежние пути команд. Для текущих запусков используйте этот README.
