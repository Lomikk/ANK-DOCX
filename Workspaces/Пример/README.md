# Учебный пример работы

`chapters/main.qmd` — полностью собираемый пример для автора и агента, а не набор несвязанных фрагментов. Все исходные параметры и научная модель находятся в одной скрытой R-ячейке `calculate-model`. При `a = 3` суммарный показатель равен 108; при `a = 5` — 166. Текст, таблицы, графики и экспорт используют эти же результаты.

## Где смотреть элементы

| Элемент | Место в main.qmd / механизм |
|---|---|
| Титул, задание, аннотация | Формы выбираются профилем из `metadata.yml`; календарный план и сведения о подписантах задаются метаданными, статистика аннотации вычисляется при сборке |
| Оглавление и четыре уровня заголовков | Введение, математическая модель и вложенные подразделы; нативные стили Word |
| Ненумерованные структурные заголовки | `.unnumbered`: введение, заключение, список литературы |
| Вычисления и inline R | `calculate-model`; числа в абзацах и математических обозначениях |
| Формулы и пояснения новых символов | `eq-model`, `eq-total`, `Formula Definitions`; повторные символы не расшифровываются повторно |
| Ссылки на формулы, разделы, таблицы, рисунки | Стандартные `[-@eq-model]`, `[-@sec-model]`, `[-@tbl-results]`, `[-@fig-functions]`; поле REF Word |
| Flextable, объединения, два уровня шапки | `tbl-results`; OMML-подстановки, вычисляемый итог и footer-примечание |
| Простая Markdown-таблица | `tbl-parameters` в приложении; значения из того же R-объекта |
| Длинная таблица | `tbl-long-results` в приложении: 55 строк, повторяемая объединённая шапка, OMML, итог, примечание и автоматические продолжения Word |
| Линии, маркеры, математическая легенда | `fig-functions`; общая тема расширения не повторяется |
| Столбцы со штриховками | `fig-patterns`, ggpattern |
| Каркасная и затенённая поверхность | `fig-surface-wire`, `fig-surface-shaded`, общая функция `ank_persp_3d()` |
| SVG, PNG 600 dpi и CSV отдельно | `export-results` → `_output/assets/`; повторного расчёта модели нет |
| Пояснительная сноска | `[^synthetic-data]`, настоящий объект footnote Word |
| Абзацное примечание и именованная ссылка | `note-rounding`; обычный Div и Markdown-ссылка, без callout с неподтверждённой закладкой |
| Примечание внутри таблицы | Footer flextable; в длинной таблице остаётся в последней физической части |
| Статья, книга, интернет-источник | `references.bib`, Citeproc; повторная, групповая и постраничная ссылки |
| Исполняемый листинг | `validate-model`, `lst-label` и `lst-cap`; ошибки проверки прекращают сборку |
| Неисполняемый листинг | Обычный блок `.r` с `#lst-consumer`; второй вычислительный движок не запускается |
| Полный исходный код без копирования | `show-calculation`: штатный knitr `ref.label`, `eval: false`, `echo: true` |
| Приложения в одном файле | Заголовки `.appendix` после списка литературы; автоматические А/Б, страницы, TOC и номера таблиц |

## Как использовать пример

Метаданные примера выбирают `academic.standard: susu-04-2008`. Титул имеет рамку, задание и календарный план — собственный бланк без рамки, аннотация — форму 2, дальнейшие страницы — форму 2а. Номера и общее число листов вычисляет Word. Чтобы проверить тот же текст без технических рамок, задайте `susu-21-2008`; для реферата используйте `profile: referat` и `standard: susu-17-2008`.

Этот пример хранится только в репозитории ANK. Новая работа получает чистый `chapters/main.qmd`, пустую библиографию и метаданные для заполнения. Читайте пример как справочник и переносите только нужные приёмы. Сохраняйте служебную setup-ячейку, согласованность результатов и стандартный синтаксис QMD. Научная модель, результат вычисления и его оформление имеют разные обязанности.

Из корня репозитория один раз выполните `setup-academic.cmd`, затем `ANK-DOCX.cmd build "Пример"`. Из подготовленного каталога примера также работает `quarto render`. Перед пересборкой закройте целевой DOCX в Word либо укажите другое имя через `--output`.

Общее оформление: ссылки имеют цвет основного текста, подписи рисунков и отдельные формулы центрируются, номер формулы остаётся справа. Во всех таблицах базовый кегль текста и формул — 11 пт. Простая Markdown-таблица в приложении получает сетку из общего reference DOCX; заменять её на flextable ради оформления не требуется.

Для нового элемента добавьте минимальный реально собираемый пример в этот QMD, строку в данный каталог и проверку результата. Если элемент ещё не поддержан, сначала отметьте ограничение и проверьте готовое средство; не изображайте его готовность текстовой заглушкой.

## Границы

Формы листов основаны на СТО ЮУрГУ 21–2008 и 17–2008 и наработках оригинального ANK; организационные и персональные данные примера учебные. Применимость к кафедре и её локальные требования необходимо подтвердить отдельно; полный нормоконтроль не заявляется. Номера листингов формирует Quarto: в однофайловом проекте они сквозные и статические; обновление после ручной перестановки требует пересборки. Подразделы приложений пока оформляются с `.unnumbered`, поскольку отдельная нумерация вида А.1 для разделов Word ещё не реализована. Многостраничные приложения пока не получают автоматические надписи продолжения приложения. Ссылки и список Citeproc не являются менеджером источников Word. Табличные продолжения рассчитаны при сборке; произвольное последующее редактирование Word не перераспределяет строки между частями автоматически.

Непроверенные компоненты Officeverse, редактируемые диаграммы Word, рамки и полный нормативный контроль в пример не включены как готовые возможности. Официальный класс `.appendix` расширен нашим DOCX-адаптером; нативная статья Quarto поддерживает его для HTML. Стандартный Book с `book.appendices` также поддерживается.
