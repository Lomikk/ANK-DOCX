# ANK DOCX

Один Quarto Starter Template для академических работ Microsoft Word. Содержательный текст находится в `chapters/main.qmd`, сведения о работе — в `metadata.yml`, источники — в `references.bib`. Делить текст на файлы по главам не требуется.

Версия 0.2.0 выделяет шаблон из исследовательского примера. `academic.profile` выбирает готовый состав документа: `coursework` или `referat`. Общие стили и реализация находятся в одном расширении. **Сопроводительные листы пока являются явно обозначенными заглушками; состав профилей не подтверждает нормативные требования СТО.**

Starter содержит полноценную учебную работу: единый расчёт R, формулы, таблицы с OMML и продолжениями, графики, сноску, примечания, библиографию, листинги и приложения в одном QMD. Каталог элементов и правила расширения примера — [quarto/EXAMPLE_GUIDE.md](quarto/EXAMPLE_GUIDE.md). При изменении `a` с 3 на 5 общий результат меняется со 108 на 166 во всех представлениях.

## Создание работы

После подготовки инструментов выполните в пустой папке новой работы:

```powershell
quarto use template "D:/Repos/ANK DOCX/quarto" --no-prompt
Rscript --vanilla tools/install.R
quarto render
```

Это штатный механизм Quarto. В опубликованном репозитории источником может служить `Lomikk/ANK-DOCX/quarto@<тег>`; новый Starter пока находится в рабочем дереве, его тег и выпуск не опубликованы.

В каждой работе заполните `metadata.yml` и редактируйте `chapters/main.qmd`. Выберите `academic.profile: coursework` или `referat`; список листов в работу не копируется. Курсовая и реферат создаются в двух самостоятельных папках с одинаковой структурой.

Для сборки нужны Quarto 1.10.19, R 4.6.1 с восстановленными renv-пакетами, `rsvg-convert`, опубликованное приложение `academic-docx` 0.2.x и настольный Word под Windows. Приложение находится через PATH; явный путь можно задать переменной `ACADEMIC_DOCX_SERVICE`. Отсутствующее или несовместимое приложение вызывает ошибку. Чужой репозиторий рядом с работой не требуется.

Подробности установки, структуры и обновлений: [Starter Template](docs/STARTER_TEMPLATE.md). Инструкция, попадающая в новую работу: [quarto/AGENTS.md](quarto/AGENTS.md). Подробные авторские правила: [docs/AUTHORING.md](docs/AUTHORING.md).

## Среда разработчика

На Windows нужны .NET 10 SDK, официальная Word PIA и настольный Word:

```powershell
.\setup-academic.cmd
.\build-academic.cmd
.\build-academic.cmd --profile referat
```

Setup публикует C#-приложение в `.tools/academic-docx/`, подготавливает закреплённые инструменты и R-пакеты. В Book-пример расширение и проектная точка входа устанавливаются из `quarto/`; их копии в примере игнорируются Git. Изменения библиотеки делайте в `quarto/_extensions/academic/`, затем повторяйте setup для обновления примера.

Без аргумента `build-academic.cmd` собирает интеграционный Book-пример: `examples/book/_book/coursework.docx`. Его вариант `referat` выпускается из того же демонстрационного содержания. Это сохранённая проверка многофайловой сборки и приложений, а не обязательная структура новой работы.

Для сборки самостоятельного проекта подготовленными инструментами репозитория передайте путь штатному Quarto:

```powershell
.\build-academic.cmd "D:/Учеба/Моя курсовая"
```

Закройте целевой DOCX перед пересборкой либо задайте другое имя через `--output`. Результат обычного проекта находится в `_output/`; Quarto сохраняет вложенный путь исходника, например `_output/chapters/main.docx`.

## Структура репозитория

| Каталог | Назначение |
|---|---|
| `quarto/` | Единственный поставляемый Starter, R lock-файл и исходники расширения |
| `examples/book/` | Сохранённый Book-пример: расчёты, flextable, OMML, длинные таблицы и приложения |
| `examples/objects/` | Отдельные образцы текста, графиков и листингов |
| `tools/AcademicDocx/` | C#-приложение: установка среды, Word-финализация, проверки и PDF |
| `tools/AcademicDocx.Core/` | Переносимая обработка DOCX через Open XML SDK |
| `tools/AcademicDocx.Tests/` | Проверки SDK, Word и создания независимых проектов из Starter |
| `docs/` | Решения, авторские правила и результаты исследований |
| `build/`, `output/` | Воспроизводимые проверки, графики и PDF |
| `.tools/` | Локальные инструменты разработчика |
| `archive/` | Локальная история опытов; не является зависимостью |

## Проверки и ограничения

```powershell
.\academic-docx.cmd validate examples/book/_book/coursework.docx
.\academic-docx.cmd check-word examples/book/_book/coursework.docx build/qa/copy.docx build/qa/word.json
.\academic-docx.cmd export-pdf examples/book/_book/coursework.docx output/coursework.pdf build/qa/pdf.json
```

Проверены нативные заголовки, TOC, SEQ/REF, редактируемая математика OMML и поддержанные таблицы. Графики строятся преимущественно ggplot2, SVG создаётся svglite; TeX для сборки не нужен. Библиографию обрабатывает штатный Citeproc. Полный нормативный профиль и автоматический анализ вёрстки ещё не реализованы.

Готовый выпуск требует Word: промежуточный пакет имеет известные ошибки схемы, после нормализации проверенные документы проходят SDK без ошибок. `ACADEMIC_SKIP_WORD=1` предназначен только для диагностики. Схемная проверка не заменяет проверку поведения в Word, а пересборка заменяет ручные правки DOCX.

Документация: [docs/README.md](docs/README.md). При переносе сохранены возможности bundle приложений из коммита `0093eec`; правила и ограничения находятся в [APPENDIX_RULES.md](docs/APPENDIX_RULES.md). AutoNormoKontrol остаётся отдельным неизменённым проектом.
