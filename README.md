# ANK DOCX

Один Quarto Starter Template для академических работ Microsoft Word. Содержательный текст находится в `chapters/main.qmd`, сведения о работе — в `metadata.yml`, источники — в `references.bib`. Делить текст на файлы по главам не требуется.

Версия 0.4.2 задаёт для текста и формул в таблицах 12 пт и сохраняет техническую курсовую по СТО ЮУрГУ 04–2008: нормативные рамки, формы 2/2а и автоматические номера листов. `academic.profile` выбирает готовый комплект: `coursework-susu-21-2008`, `referat-susu-17-2008` или `coursework-susu-04-2008`; исследовательская ВКР доступна как экспериментальный `research-susu-19-2008`. Для НИР добавлены виды приложений, общий заголовок и автоматические надписи продолжения. Старые короткие имена и допустимые сочетания с `academic.standard` сохраняются. Общие стили и вычисления остаются едиными, статистика аннотации вычисляется при сборке. Применимость к кафедре и локальные требования проверяются отдельно: [правила и ограничения](docs/FRONT_MATTER.md).

Новая работа начинается с чистого `chapters/main.qmd` (только служебная setup-ячейка), незаполненных метаданных и пустой библиографии. Полная учебная работа и каталог элементов хранятся отдельно в [Workspaces/Пример/](Workspaces/Пример/README.md) и в новые работы не копируются. renv сохраняет версии зависимостей каждой работы, а установленные пакеты использует через ссылки на общий кэш.

## Создание работы

После клонирования репозитория выполните в его корне:

```powershell
.\ANK-DOCX.cmd setup
.\ANK-DOCX.cmd new "Моя курсовая"
.\ANK-DOCX.cmd new "Мой реферат" --profile referat
```

Нужны Windows, .NET 10 SDK, официальная Word PIA и настольный Word. Setup установит остальные закреплённые зависимости. Новые работы находятся в `Workspaces/<название>/`, этот каталог игнорируется Git репозитория ANK, кроме поставляемого примера `Workspaces/Пример/`.

В репозитории уже есть одна демонстрационная работа — `Workspaces/Пример/`. После setup её можно открыть в редакторе и собрать командой `.\ANK-DOCX.cmd build "Пример"`. Внутри README с каталогом поддержанных элементов.

Откройте папку своей работы в редакторе, заполните `metadata.yml` и напишите текст в `chapters/main.qmd`. Затем из корня репозитория:

```powershell
.\ANK-DOCX.cmd build "Моя курсовая"
.\ANK-DOCX.cmd list
```

Результат: `Workspaces/Моя курсовая/_output/chapters/main.docx`. Перед пересборкой закройте этот DOCX в Word. Запуск `ANK-DOCX.cmd` без аргументов открывает меню создания, сборки и списка работ. Имя — название одной папки, не путь. Существующая папка командой `new` не перезаписывается. По умолчанию профиль — `coursework`; также доступен `referat`.

CMD вызывает штатные `quarto use template`, `renv::restore` и `quarto render`. Общая реализация хранится в репозитории, работа получает установленное расширение. Пакеты R используются ссылками на общий кэш. Пользовательские работы при необходимости могут иметь свой отдельный Git-репозиторий.

Внешние папки также поддерживаются: [создание через Quarto и подготовка окружения](docs/STARTER_TEMPLATE.md). Путь `Lomikk/ANK-DOCX/quarto@<тег>` станет доступен после публикации выпуска; сейчас используется локальный Starter.

## Среда разработчика

На Windows нужны .NET 10 SDK, официальная Word PIA и настольный Word:

```powershell
.\setup-academic.cmd
.\build-academic.cmd
.\build-academic.cmd --profile referat
```

Setup публикует C#-приложение в `.tools/academic-docx/`, подготавливает закреплённые инструменты и R-пакеты. В Book-пример расширение и проектная точка входа устанавливаются из `quarto/`; их копии в примере игнорируются Git. Изменения библиотеки делайте в `quarto/_extensions/academic/`, затем повторяйте setup для обновления примера.

Без аргумента `build-academic.cmd` собирает интеграционный Book-пример: `examples/book/_book/coursework.docx`. Его вариант `referat` выпускается из того же демонстрационного содержания. Это сохранённая проверка многофайловой сборки и приложений, а не обязательная структура новой работы.

Для сборки самостоятельного проекта подготовленными инструментами репозитория передайте путь штатному Quarto:

```powershell
.\build-academic.cmd "D:/Учеба/Моя курсовая"
```

Закройте целевой DOCX перед пересборкой либо задайте другое имя через `--output`. Результат обычного проекта находится в `_output/`; Quarto сохраняет вложенный путь исходника, например `_output/chapters/main.docx`.

## Структура репозитория

| Каталог | Назначение |
|---|---|
| `Workspaces/` | Пользовательские работы игнорируются Git; Пример/ поставляется в репозитории |
| `quarto/` | Единственный поставляемый Starter, R lock-файл и исходники расширения |
| `examples/book/` | Сохранённый Book-пример: расчёты, flextable, OMML, длинные таблицы и приложения |
| `Workspaces/Пример/` | Полный учебный пример и каталог для агента; в Starter не входит |
| `examples/objects/` | Отдельные образцы текста, графиков и листингов |
| `tools/AcademicDocx/` | C#-приложение: установка среды, Word-финализация, проверки и PDF |
| `tools/AcademicDocx.Core/` | Переносимая обработка DOCX через Open XML SDK |
| `tools/AcademicDocx.Tests/` | Проверки SDK, Word и создания независимых проектов из Starter |
| `docs/` | Решения, авторские правила и результаты исследований |
| `build/`, `output/` | Воспроизводимые проверки, графики и PDF |
| `.tools/` | Локальные инструменты разработчика |
| `archive/` | Локальная история опытов; не является зависимостью |

## Проверки и ограничения

```powershell
.\academic-docx.cmd validate examples/book/_book/coursework.docx
.\academic-docx.cmd check-word examples/book/_book/coursework.docx build/qa/copy.docx build/qa/word.json
.\academic-docx.cmd export-pdf examples/book/_book/coursework.docx output/coursework.pdf build/qa/pdf.json
```

Проверены нативные заголовки, TOC, SEQ/REF, редактируемая математика OMML и поддержанные таблицы. Графики строятся преимущественно ggplot2, SVG создаётся svglite; TeX для сборки не нужен. Библиографию обрабатывает штатный Citeproc. Полный нормативный профиль и автоматический анализ вёрстки ещё не реализованы.

Готовый выпуск требует Word: промежуточный пакет имеет известные ошибки схемы, после нормализации проверенные документы проходят SDK без ошибок. `ACADEMIC_SKIP_WORD=1` предназначен только для диагностики. Схемная проверка не заменяет проверку поведения в Word, а пересборка заменяет ручные правки DOCX.

Документация: [docs/README.md](docs/README.md). При переносе сохранены возможности bundle приложений из коммита `0093eec`; правила и ограничения находятся в [APPENDIX_RULES.md](docs/APPENDIX_RULES.md). AutoNormoKontrol остаётся отдельным неизменённым проектом.
